## 🎯 Mejores Prácticas

### ✅ Qué Hacer:
1. **Sé específico**: Describe exactamente qué no funciona
2. **Incluye contexto**: Menciona qué estabas haciendo cuando ocurrió
3. **Usa el nivel apropiado**: Compacto para problemas simples, completo para complejos
4. **Confía en el sistema**: Deja que ejecute las 5 fases automáticamente

### ❌ Qué NO Hacer:
1. **No seas vago**: "No funciona" no es suficiente información
2. **No interrumpas**: Deja que complete todo el flujo automático
3. **No pidas cambios manuales**: El sistema está diseñado para ser automático
4. **No ignores los tests**: Si fallan, hay un problema real

## 📊 Qué Esperar del Sistema

### Respuesta Automática Típica:
1. **Análisis**: "Analizando el problema de comunicación WebSocket..."
2. **Diagnóstico**: "He identificado que el issue está en..."
3. **Implementación**: "Implementando la solución..."
4. **Validación**: "Ejecutando tests automáticos..."
5. **Resultado**: "Solución implementada y validada ✅"

### Indicadores de Éxito:
- ✅ Tests pasando al 100%
- ✅ Preview visual si hay cambios UI
- ✅ Funcionalidad restaurada/implementada
- ✅ Documentación actualizada
- ✅ Sin regresiones en funcionalidades existentes

## 🚨 Solución de Problemas del Sistema

### Si el prompt no funciona como esperado:
1. **Verifica la sintaxis**: Usa exactamente los formatos mostrados
2. **Sé más específico**: Agrega más detalles del problema
3. **Usa el nivel correcto**: Problemas simples → compacto, complejos → completo
4. **Revisa el contexto**: Asegúrate de estar en el proyecto correcto

### Si los tests fallan:
1. **No ignores**: Los tests fallan por una razón
2. **Revisa el output**: Lee los mensajes de error
3. **Pide análisis**: Usa el prompt para que analice los fallos
4. **Valida manualmente**: Comprueba que la funcionalidad realmente funciona
